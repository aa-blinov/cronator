# UX Map — все действия пользователя

Карта пользовательского опыта: каждый путь от первого контакта до результата,
чем он заканчивается и где было тесно. Аудит проведён на живом приложении
(SQLite, локальный запуск) — каждый статус в таблицах получен реальным
запросом, не из чтения кода.

## Путь 1. Первый запуск (критический: без него UX нет вообще)

```
git clone → cp .env.example .env → заполнить 3 значения → uv sync →
→ alembic upgrade head → uvicorn start → http://localhost:8080
```

| Шаг | Что видит пользователь | Статус |
| --- | --- | --- |
| `cp .env.example .env` | README подсказывает; Windows-пользователь имеет `start.bat`, который делает copy сам | OK |
| `alembic upgrade head` | ~~`OperationalError: near "ALTER"` — миграции падают на SQLite~~ | **FIXED**: `server_default` и FK переписаны через `batch_alter_table`; вся цепочка прогоняется на чистой SQLite регрессионным тестом |
| `downgrade base` (сброс) | ~~падал на той же миграции~~ | проверено: `returncode 0` на свежей базе и обратно |
| Открытие :8080 | dashboard отдаётся 200, `last_run_status`-словарь согласован | OK |

## Выводы аудита

1. **Самый большой UX-разрыв был не в интерфейсе, а в первом запуске** —
   локальный путь (SQLite) падал на миграциях и убивал весь дальнейший опыт.
   Починено и закрыто регрессионным тестом.
2. **Тупик 404** — единственная найденная дыра в самом интерфейсе; починена
   переиспользованием уже существующей страницы ошибки.
3. Редактор, подтверждения, тосты и статусы — уже на продакшн-уровне;
   ломать не стали и не трогали.

**Поправка к вердикту:** пункт про viewer в исходном вердикте был
неточным — код скрывает все admin-действия от viewer'а (`is_admin`-гейты
покрывают панели списков и детальные страницы; проверено живыми
 запросами под read-only-аккаунтом: 0 видимых кнопок, bulk-панели нет).
«Мелочь» снята.

## Аудит числа кликов

Замер по каждому сценарию, «клики» — фактически требуемые нажатия (набор
текста не считается). Замер по шаблонам и маршрутам приложения; кнопка Run
Test в редакторе уже объединяет сохранение и запуск, поэтому «Save & Run»
не потребовался.

### До

| Сценарий | Кликов до | Почему |
| --- | --- | --- |
| Запустить сохранённый скрипт | 2 (View → Run) | в строке списка только «View» |
| Увидеть результат запуска | +0 (Run ведёт на страницу запуска) | редирект уже правильный |
| Включить/выключить скрипт | 2 (View → Disable) | тумблер только в detail |
| Посмотреть историю запусков с точки «list» | 2 (View → scroll) | «Last Run» — мёртвый текст |
| Повторить запуск из истории (раннее был известный результат) | 2 (View Logs → повторный Rerun) | Rerun только в detail |

### План минимизации → реализовано

| Рация | План | Статус |
| --- | --- | --- |
| Run в строке списка скриптов | POST `/scripts/{id}/run` прямо из списка; он уже ведет на страницу запуска → результат в 1 клик | **Сделано** |
| Тумблер Enable/Disable в строке | POST `/scripts/{id}/toggle?next=/scripts` — возврат на список, флейш-тост уже есть (`consumeQueuedToast`); `next` — относительный путь с guard от open-redirect | **Сделано** |
| «Last Run» → история скрипта | ссылка в `/executions?script_id={id}` (фильтр уже был на сервере) | **Сделано** |
| Rerun в строке исторических запусков | POST `/executions/{id}/rerun` — уже ведёт на новый запуск | **Сделано** |
| «History» в строке запусков | ссылка на все запуски скрипта | **Сделано** |

### После

| Сценарий | Кликов | Дельта |
| --- | --- | --- |
| Запустить скрипт | 1 | −1..−2 |
| Включить/выключить | 1 | −1 |
| История с точки списка | 1 | −1 |
| Повторить удачный запуск | 1 | −1 |

Все четыре сценария проверены на живом приложении POST-запросами:
Run в строке (303 на страницу запуска), Rerun в строке (303 на новый
запуск в 1 клик), тумблер Enable/Disable из списка (303 на список,
статус переключается и фиксируется), «Last Run» как ссылка на историю.
`?next=//evil.example` отклонён guard-ом — редирект остаётся относительным
(`test_next_redirect_guard.py`, 12 passed).

Частотный сценарий (запуск) стал одно-кликовым в обе стороны истории:
запущенно — и с точек списка, и с точки исторической записи. Логика

## Вес страниц (замер после закрытия мелочей)

| Страница | Было (шаблоны встроены) | Стало (ленивая загрузка) |
| --- | --- | --- |
| Новый скрипт (редактор) | 169 KB | **125 KB (128 914 B)**, по gzip — ~27 KB |
| Дельта | мёртвый JSON 19 шаблонов в каждой странице (~45 KB) | один кэшируемый запрос `/api/scripts/templates` при первом открытии модалки |
безопасности: подтверждающие диалоги удалений/отмены не сокращены —
сознательно, цена лишнего клика ниже цены случайной потери.

### Скорость

- GZip уже включён (>= 500 байт), статика с `Cache-Control (CachedStaticFiles)`.
- Дальнейший резерв (сжатие таблиц списков до строки actions) оценён как
  отрицательный: только что замерили 169KB редактор и 20–50KB списки, это
  норма для самохостинга и телефонов уже достаточно.
