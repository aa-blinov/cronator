# UX Map — все действия пользователя

Карта пользовательского опыта: каждый путь от первого контакта до результата,
чем он заканчивается и где было тесно. Аудит проведён на живом приложении
(SQLite, локальный запуск) — каждый статус в таблицах получен реальным
запросом, не из чтения кода.

## Путь 1. Первый запуск (критический: без него UX нет вообще)

```
git clone → cp .env.example .env → заполнить 3 значения → uv sync →
→ alembic upgrade head → uvicorn start → http://localhost:8080
```

| Шаг | Что видит пользователь | Статус |
| --- | --- | --- |
| `cp .env.example .env` | README подсказывает; Windows-пользователь имеет `start.bat`, который делает copy сам | OK |
| `alembic upgrade head` | ~~`OperationalError: near "ALTER"` — миграции падают на SQLite~~ | **FIXED**: `server_default` и FK переписаны через `batch_alter_table`; вся цепочка прогоняется на чистой SQLite регрессионным тестом |
| `downgrade base` (сброс) | ~~падал на той же миграции~~ | проверено: `returncode 0` на свежей базе и обратно |
| Открытие :8080 | dashboard отдаётся 200, `last_run_status`-словарь согласован | OK |

## Путь 2. Создание и настройка скрипта

```
Dashboard → New Script → редактор (выбор из 19 шаблонов, cron, пакеты,
env-переменные) → Save → перенос в режим установки → интал пакетов (SSE-стрим)
```

| Шаг | Что видит пользователь | Статус |
| --- | --- | --- |
| Открыть редактор | 169KB страница, шаблоны встроены, подсветка синтаксиса | OK |
| Сохранить с плохим именем (`ux audit &PAR!`) | тост `Error: Name can only contain letters, numbers, underscores, and hyphens` | OK — формулировка описывает правило и решение |
| Сохранить с кривым cron | тост `Error: Cron expression must have 5 parts (minute hour day month weekday)` | OK |
| Дубликат имени | `Error: Script with this name already exists` | OK |
| Save | тост `Script created successfully` + установка зависимостей со статусами и Retry при падении | OK |

## Путь 3. Запуск и наблюдение

```
Script detail → Run → кнопка переключается в «выполняется» →
→ детальная страница запуска со stdout/stderr → Executions list → история
```

| Шаг | Что видит пользователь | Статус |
| --- | --- | --- |
| Run | `execution_id` + статус polling на `/api/scripts/{id}` | OK |
| Результат | страница запуска 49KB, вывод `Hello from Cronator!` виден, логи и в HTML, и через `/api/executions/{id}/logs/stdout` | OK |
| Rerun/Cancel | отдельные кнопки, Cancel — с подтверждением | OK |
| Удалить скрипт | confirm с явным перечислением последствий (среда, задания, история) | OK |

## Путь 4. Ошибки и тупики

| Сценарий | Что видел пользователь | Статус |
| --- | --- | --- |
| Опечатка в URL (`/no-such-page`) | ~~голый JSON `{"detail":"Not Found"}`, никуда не деться~~ | **FIXED**: оформленная страница с кнопкой «Back to Dashboard», тема сохраняется |
| Открыть удалённый скрипт/запуск | то же | **FIXED** |
| 404 на `/api/…` | JSON `{"detail": ...}` — правильно для клиентского кода | OK (не тронуто) |
| 401 на страницу | нативный Basic Auth-промпт браузера | OK (выведено из HTML-обработчика сознательно) |
| 403 (viewer жмёт кнопку) | HTML-страница «Access Denied» с возвратом | OK (уже было) |

## Путь 5. Операционные экраны

Settings (41KB), Users (25KB), Changelog (50KB), Dashboard (23KB) — все 200,

## Выводы аудита

1. **Самый большой UX-разрыв был не в интерфейсе, а в первом запуске** —
   локальный путь (SQLite) падал на миграциях и убивал весь дальнейший опыт.
   Починено и закрыто регрессионным тестом.
2. **Тупик 404** — единственная найденная дыра в самом интерфейсе; починена
   переиспользованием уже существующей страницы ошибки.
3. Редактор, подтверждения, тосты и статусы — уже на продакшн-уровне;
   ломать не стали и не трогали.
